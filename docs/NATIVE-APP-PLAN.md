# QuestBoard ネイティブ版 MVP スコープ ＋ 課金設計

作成日: 2026-06-09
方針決定: Web版(Next.js)から **iOSネイティブ(SwiftUI)へ作り直し** ＋ マネタイズ導入。Android は iOS先行リリース後に後追い。

---

## 0. 背景

- 現Web版は本番稼働中（https://myquestboard.entaku.app）だが流入ゼロ（users=1 / DAU=0）。
- 機能・技術的負債は無く「綺麗に止まった」状態。足りないのは流入。
- ストア配信（App Store / Google Play）を**新しい流入チャネル(ASO・ストア検索)**として位置づけ、同時にマネタイズの箱を作る。
- バックエンド(Firebase: Auth + Firestore)は**流用**。作り直すのはクライアントのみ。

---

## 1. MVP スコープ

### ✅ MVPに入れる（コア体験）

| 機能 | 内容 | 由来 |
|------|------|------|
| やりたいことリスト | 項目CRUD。title / category / deadline / notes / status(未着手・進行中・完了) | Web: BucketList |
| サブアクション | 各項目に小タスク(text/done)をぶら下げる | Web: Action[] |
| カテゴリ分類 | 旅行・学習・体験・創作・健康・その他 | Web: CATEGORIES |
| 達成シェア | 完了項目をシェアカード画像化 → SNS/LINE | Web: ShareCard |
| ガチャ提案 | ランダムに「やりたいこと」を提案して着想を促す | Web: GACHA_ITEMS |
| 認証 | Firebase Auth（**Sign in with Apple + Google**。Google経由でWeb版とデータ共有が繋がる） | Web: AuthButton |
| クラウド同期 | Firestore でデバイス間同期（Web版とデータ共通） | Web: onSnapshot |
| オンボーディング | 初回の使い方ガイド | Web: チュートリアル |

### ⏸ MVPでは切る（v1.1以降）

- **目標ピラミッド**（夢→目標→タスク3層）… コア体験が固まってから。MVPは「リスト＋達成シェア」に一点集中。
- 進捗グラフ(StatsCard)… あったら嬉しいが必須ではない。
- プッシュ通知（締切リマインダー）… v1.1の目玉候補。
- 多言語化… まず日本語。

### 受け皿として残すWeb資産

- `/share/[uid]` のOGP共有ページ → アプリからシェア → Webで開くとOGP表示。**作り直してもこの導線はそのまま活きる。**

---

## 2. データモデル（Firestore流用）

既存スキーマをそのまま使う。クライアントが変わるだけ。

```
users/{uid}                         … ユーザー
appStats/summary                    … dauTotal, shareTotal
appStats/daily/{date}/{uid}         … 日別DAU
（やりたいことリスト本体は現状 doc(uid) に集約 / ネイティブも同じドキュメントを読み書き）
```

→ Web版とネイティブ版で**同一データ**。片方で追加した項目がもう片方に出る。移行コストゼロ。

## 3. 技術スタック

| 領域 | 選定 |
|------|------|
| iOS UI | SwiftUI |
| バックエンド | Firebase Auth + Firestore（流用） |
| iOS Firebase | firebase-ios-sdk (SPM) |

## 4. マネタイズ設計

### 価格（買い切り一本に確定 / 2026-06-09）

| プラン | 金額 | 位置づけ |
|--------|------|----------|
| 買い切り | ¥980「永久プレミアム」 | **これ一本**。一度払えば永久。サブスク無し |

- サブスク（月額・年額）は**やらない**。意思決定の単純さ・買い切り心理・サブスク疲れ回避を優先。
- トレードオフ: LTV頭打ち・継続収益なし。個人アプリ規模では「迷わず一回払って終わり」を優先する判断。
- StoreKit的には **non-consumable（消耗しない App内課金）1種**のみ。実装が最もシンプル。

### 課金トリガー（無料に制約を仕込まない方針）

- **プレミアム = シェアカードのテーマ**（ゴールド初手 → ライト → ミニマル）
- コンセプト: 「無料では届かないかっこよさ」を後乗せ。無料でも全機能使える。
- 動線: 達成 → シェアカード生成 → 「ゴールドテーマで自慢する？」→ 課金
- 自前のPaywall画面で買い切り¥980を1つ提示 → 購入 → プレミアム解放。

### なぜこの設計か

- 機能制限ではなく「見た目の特別感」で課金 → コンセプト(達成をシェアして自慢)と自然に合致。
- 達成という最もポジティブな瞬間に課金導線を置く＝CVRが高いはず。

## 5. リリースまでのステップ（iOS）

1. 同リポジトリ `ios/` にSwiftUI Xcodeプロジェクト作成 + Firebase SDK(SPM)接続 + iOS用 .gitignore 追記（DerivedData / *.xcuserstate 等）

3. やりたいことリスト CRUD + カテゴリ/ステータス/サブアクション
4. ガチャ提案
5. シェアカード生成（画像 → 共有シート → Web /share 連携）
6. オンボーディング
7. StoreKit2 組み込み（買い切り1種）+ Paywall + プレミアムテーマ + 購入復元
8. App Store メタデータ・スクショ（既存スキル: ios-screenshot / fastlane-release）
9. TestFlight → 審査 → リリース

## リスクメモ（PdM所感）

流入ゼロのままストア＋課金の箱を作ると、Web版と同じ「箱は立派・中身ゼロ」を繰り返す恐れ。
ストア掲載自体が流入チャネルになる前提なので、**リリース＝ゴールではなくASO/ストア最適化までがセット**。
リリース後は「ストア表示回数→DL→課金」のファネルを必ず計測する。
